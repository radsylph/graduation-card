# Menu Page — Plan

Status: Approved · 2026-10-04

## Goal

Add a menu page at `/menu` showing the full Aliño Restaurante menu (categories,
items, descriptions, prices, and photos), and link to it from the invitation.
The menu is display-only: guests browse but do not order through the site.

## Decisions

- **Route**: `/menu` is its own page; the invitation gets a "Ver menú" button.
- **Scope**: the entire restaurant menu (~207 items across 10 categories), not a
  curated event subset.
- **Source of truth**: `src/data/menu.json`, generated by
  `scripts/scrape-menu.mjs`, which parses the restaurant's server-rendered page
  and writes the JSON. The JSON is committed so the site never depends on a live
  request at build time; the script is re-run when the menu changes.
- **No ordering**: guests are not asked to order or pay; there is no cart, no
  Flujia widget, and no per-item deep links. Items are rendered read-only.
- **Prices**: shown as-is (USD), including promo items (old price struck through
  with a "★ PROMO" ribbon).
- **Photos**: hotlinked from the restaurant's CDN (`alinorestaurante.com`), with
  `loading="lazy"`.
- **Navigation**: a sticky category pill nav (anchor links) mirrors the
  restaurant's own nav; no search or pagination.
- **Styling**: reuses the invitation palette and fonts (parchment background,
  gold/crimson headings, white cards with gold borders).

## Implementation notes

- The scraper parses each `<section class="cat-sec">` for the category name and
  each `<a class="prod-card">` for name, description, price, optional old price,
  promo flag, image URL, and product href. Prices are stored as numbers and
  formatted with `toFixed(2)` at render time.
- Images keep the restaurant's `unique=` cache-buster query so the exact asset
  version is referenced; re-scraping refreshes it.
- Long descriptions are clamped to two lines (`line-clamp-2`).
